整理日期：2026-10-21  
状态：需求设计草案；“已确认”来自本次讨论，其余为首版建议，尚未视为全部定案。

## 1. 首版目标

让多位老师维护班级与学生，基于真实课程大纲、每周教学进度、寒暑假集训和考试目标，生成可解释、可编辑的个人学习路线与学习规划书，导出 PDF 后由老师发送给家长。

首版闭环：

公共课程及目标资料 → 班级与学生档案 → 输入规划条件 → 自动生成路线 → 老师调整 → 定稿留存 → 导出 PDF。

不单独做复杂统计首页。登录后建议进入“我的班级”，从学生进入规划流程。

### 3.2 账号与权限建议

- 管理员：管理老师账号及班级分配，维护公共课程、考纲与集训资料，可查看全校区规划。
- 老师：查看与编辑分配给自己的班级及学生；读取公共资料；创建和修改授权范围内的规划。
- 同一班级可分配多位老师，避免把学生永久绑定到单个老师。
- 权限在服务端校验；不能仅靠前端隐藏按钮。
- 首版家长没有登录账号。对外交付为老师下载的PDF。

以上具体权限分工是首版建议；多位老师使用、家长接收PDF已确认。

### 3.3 首版不纳入

- 家长／学生登录端、在线聊天、自动发送PDF。
- 在线判题、完整题库、作业系统、收费与课消、考勤系统。
- 多校区经营管理、复杂审批流程和经营统计看板。
- 自动抓取并更新考试政策。
- 任意图片／PDF上传后无人校验直接入库。
- 多套可视化排版模板及自由拖拽模板编辑器。

首批资料先整理核对后导入；后台保留常规编辑能力。暂不将自动OCR导入平台作为首版前置任务。

## 4. 规划生成器的交互设计

### 第一步：确定学生起点

1. 选择班级：仅显示当前老师有权限的班级。
2. 选择学生：筛选为所选班级的学生；换班时清空或重新选择学生，不能保留其他班的学生。
3. 自动显示年级（含对应学年）、所属班级、课程体系及版本、当前单元、已完成到第几节课；不在新建规划中重复手填这些档案信息。
4. 个人进度优先于班级默认进度，显示进度来源；缺失档案明确显示待补，不能猜测。
5. 换学生时清空上一学生的路线与个人建议，重新读取资料，避免串用。

还从学生档案带入：
- 当前课程版本与“已完成到第几课”。
- 已通过的GESP等级、成绩和时间。
- 个人掌握情况、测评和薄弱知识点。
- 已参加集训及完成情况。
- 班级上课日与每周频率。

建议统一输入为“已完成课次”，下一次排课从下一课开始。未开课为0。若沿用“正在学”字段，必须增加状态，避免同一课被重复安排或漏排。

### 第二步：确定规划条件

- 规划开始、结束日期，支持自定义，不能写死为一年。
- 直接选择“本次规划的目标”：GESP 1级、2级、3级、4级、5级、6级、7级、8级、CSP-J晋级、CSP-S晋级。删除“目标设置方式”字段。
- 当前线框为单个主要目标；AI可在路线中提出中间等级或阶段里程碑。多目标同时选择尚未确认，不作为既定需求。
- 目标月份为规划意向，具体考试场次及日期从有来源的数据读取。CSP晋级的具体阶段在目标库中明确；不能把初赛晋级与复赛获奖混为一谈。
- 寒假与暑假的可参加天数、可用营期。
- 已确定参加／仅供推荐的集训分别标记。
- 学生可投入的课外练习时间；未知时留空，不编造训练承诺。
- 个别停课、调课、请假作为明确例外录入；寒暑假整体默认照常上课。

“已确定／推荐”两种集训状态为产品建议，避免把尚未确定的营期计入确定性达标结论。

### 第三步：生成和编辑路线

桌面主区域以表格展示路线，不再以阶段卡片作为主布局：

| 时间 | 任务 | 核心知识点 | 目标/里程碑 |
|---|---|---|---|
| 阶段起止日期或预计月份 | 单元与具体课次、集训课程或目标核验任务 | 从已核对课程和考纲中引用本阶段学习内容 | 可检查的阶段成果、考级节点或需补齐的条件 |

- 点击“AI规划路线”，生成结构化草稿；按月份或阶段聚合课程，保留具体课次依据。
- 每行“编辑”打开四列输入，老师可修改时间、任务、知识点和里程碑，亦可新增、移除阶段。
- 编辑内容与规划书预览共用同一份路线数据；不在预览时重新调用AI另写一份。
- 另显示推荐依据、未覆盖知识、测评状态与资料缺口，不挤占四个主列。
- 行记录来源（AI／老师）、对应课程、生成版本与手工修改状态。

底层按实际课次和日期计算；老师阅读时按月份／阶段展示，必要时展开到每周与每日集训安排。

调整后展示受影响的后续节点，由老师确认应用；已手工修改的说明不被整篇重生成覆盖。保留“重新生成本阶段”的能力。

修改日期必须在正式产品中校验日期区间和排课约束；时间变化引起的后续影响与文字修改分别处理。四列可编辑不等于可以静默破坏周课顺序。

### 第四步：预览、定稿、导出

- 预览与PDF使用同一套内容。
- “整体路线图”在预览和PDF中同样使用时间、任务、核心知识点、目标/里程碑四列，保留老师的最终修改。
- 草稿可以持续编辑；定稿保存当时的课程、考纲、安排及文字快照。
- 后续修改定稿时复制为新版本，历史版本不随资料库变化。
- 导出时显示学生、规划周期、制定老师、日期及版本。

## 5. 自动规划的计算规则

### 5.1 先生成常规课日历

1. 读取开始日期、固定上课日和已完成课次。
2. 按每周一节推进一课，将U1的20课和U2—U8的12课按顺序排入。
3. 只应用明确录入的停课或调课例外，寒暑假不自动停课。
4. 第19／20课或第11／12课中的复习测评占用正常课次，不增加额外复习周。
5. 学生可继承班级进度，也可明确设置个人进度差异。

### 5.2 再安排集训

1. 冬季只从相应年份可用的D系列选择；夏季只从相应年份可用的XP系列选择。
2. 根据实际入营日期前预计完成的常规课，以及已完成集训，检查已配置的先修条件。
3. 10／20／30天方案从经确认的当季组合中选择，不跨季拼成同一次营期。
4. 所需课程或组合资料不完整时，列为“资料不足／待老师选择”，不凭编号猜测先修顺序。
5. 推荐状态的集训保留条件说明；已确定安排单独保存。
6. 集训内容计入知识覆盖与强化经历，但不自动将常规课标为已完成。
7. 每日课表保留上午、下午、晚上等时段，不能把10天直接等同于10节常规课。
8. 常规课和集训日期重叠时提示老师；不自动取消任何一条安排。

#### 寒假首营推荐方法

参考用户指定的[集训推荐页面](https://student-web.xiaomawang.com/camp_plan/camp_plan.html)中已读取的公开判断逻辑，作为可配置规则，不要求每次生成规划都访问该网页。

- 输入为课包版本、单元与课次、已参加集训。原网页的年级和线上／线下选择不参与首营等级判断。
- 原网页按“当前课次”判断；本站适配为“实际入营日期之前预计已完成课次”。同日尚未完成的周课不计入，课次含义和对应版本必须明确。
- U1新增8课后的编号需建立映射；不能默认所有AC班版本都等于网页的C++4.5版本。当前交互线框仅用示例档案演示C++4.5分支，正式映射待核对。
- C++4.5分支：达到U7第6课→D03；否则达到U5第1课→D02；否则达到U1第17课→D01；未达到则老师评估。
- 星辰班分支对应门槛为U7第6课、U5第1课、U2第2课；4.1CC分支为U3第7课→D05、U2第1课→D04，否则D03；4.0分支为U10第1课→D04，否则D03。
- 在通过课包和基础门槛后，已参加D01／XP01／XM02至少推荐D02，D02／XP02／XP03至少推荐D03，D03至少推荐D04，D04／XP04／XP05至少推荐D05。已参加D05时转老师评估。XP03B不能自动当作XP03；未知课包及基础未达到时的提前返回保留。
- 网站20／30天方案有D营衔接XP营的组合；本站按用户确认的季节规则拆分，不能将XP营排成寒假营。同季组合未配置时仅给出10天首营，其余天数标待配置。
- 推荐结果显示理由，老师可覆盖。版本、资料缺口和覆盖原因保存到规划。

### 5.3 匹配GESP／CSP目标

1. 以已核对的考试大纲版本为依据，用知识点及要求程度匹配具体课程内容。
2. 分别展示“已学覆盖”“计划覆盖”“个人掌握／待测评”，避免把未来安排当成已经掌握。
3. 基于计划覆盖时间、已知掌握情况与可用考试场次，给出建议等级与时间窗口。
4. 日期未经确认时使用预计月份或“待公布”，不生成虚假的具体考试日期。
5. 若知识缺口或时间不足，显示原因，并提供老师可选的调整方案；不自动增加复习课。
6. 未获得对应考纲或未完成映射的目标，不给出“已具备报考／通过条件”等确定结论。
7. 初赛、复赛以及具体奖项目标分别记录，不能用一个“CSP-J达标”覆盖全部要求。

目标选择范围包含全部GESP 1—8级、CSP-J晋级和CSP-S晋级。缺少某目标的大纲或课程覆盖时，仍可记录目标意向，但明确显示待补资料和不能完成的判断；不能把选项可选等同于已有完整目标路线或准备充分。

### 5.4 AI规划与规则校验的职责

- **正式MVP包含实际AI规划能力**，不能仅以静态模板替代。AI根据学生档案、可用课程、目标考纲、集训和排课约束生成四列路线，以及阶段学习建议。
- 日历和可用课次先由结构化规则计算，寒假首营使用版本化推荐规则；AI在这些事实和约束上组织任务、知识点与里程碑。
- 输出采用结构化格式，包含行ID、时间、任务、知识点、目标／里程碑、引用的课程和考纲ID、推荐理由、资料缺口；所有引用必须能回溯到已录入版本。
- 生成后验证：日期有效且在周期内、常规课不漏排重排、寒暑假照常、复习课不重复增加、营地季节与先修条件、考试日期来源、知识点来源。
- 校验失败显示原因并允许重试，不把违反约束的草稿当作完成结果；数据不足时生成可规划部分并列出缺口，不补造考纲与学生表现。
- 老师手工修改行保留并标记；条件变化后受影响的已修改行提示复核，不被整篇重生成覆盖。
- 记录AI生成版本、输入资料版本和老师调整；定稿与PDF读取同一内容快照。
- 当前v0.2线框仅演示AI入口、结果形式与编辑联动，尚未调用AI模型，也未接通真实学生库或PDF导出。示例路线由本地演示逻辑形成，不能作为已实现真实AI规划的验收依据。

## 6. 建议的数据组织

| 数据 | 关键字段或关系 |
|---|---|
| 用户与班级权限 | 老师账号、角色、可访问班级 |
| 班级 | 课程版本、授课老师、固定上课日、已完成课次、学生名单 |

| 集训课程／实际营期 | 编号及别名、季节、版本、天数、逐日课表、先修条件；年份、开营日期 |
| 集训组合 | 季节、可用营期、总天数、有序课程列表、条件 |
| 目标大纲／考试场次 | 体系、等级／阶段、要求、版本、来源；年月、日期确认状态 |
| 知识点对应关系 | 课次／集训日与目标要求的对应、覆盖程度、审核状态 |
| 规划及版本 | 学生、条件、四列路线行、阶段目标、建议、AI生成版本、修改状态、来源快照、制定人、状态 |

课程编号应保留原图名称与标准别名。例如XP03B可对应本次原图的XP03-B，但不能自动等同于未区分A／B的XP03。U1加入8课后的新课号与旧课号保留对应，不直接覆盖来源信息。

## 7. 首版PDF模板

采用一套A4模板，参考用户提供规划书的内容结构与橙蓝视觉风格，页数随内容增长。

建议章节：
1. 学生起点、规划周期、核心目标。
2. 整体路线图：时间、任务、核心知识点、目标/里程碑四列。
3. 各阶段课程、集训、任务与目标。
4. 课程与目标考纲的对照及需补内容。
5. 每周执行建议。
6. 里程碑、风险及应对。
7. 制定老师、版本和必要的资料来源说明。

需要保证：
- 文字、表格不截断；跨页表格重复四列表头，保留可读字号。
- 同一目标日期修改后，各处引用一致。
- 已有复习测评显示在原有课程安排中，不额外生成复习阶段。
- 目标为建议而非结果保证；未知日期和资料状态清楚呈现。
- 不包含无关学生信息。

## 8. 验收场景

| 场景 | 预期结果 |
|---|---|
| 班级学生联动 | 只列所选班学生；切换后年级、班级、体系、单元、已完成课次同步更新，不沿用另一学生路线 |

| 修改路线表格 | 四列均可编辑；预览和PDF逐行显示同一份修改后内容 |
| 重新规划 | 已修改行保留，条件变化时提示复核；不能静默覆盖 |
| 寒假首营 | 用已核对的课包映射、入营前课次与集训经历匹配；寒假不含XP系列 |
| U1从零开始 | 先排8课数理，再排原C++课程，最后为第19课复习和第20课测评 |
| 常规课计数 | U1—U8总104课，不因自动复习而膨胀 |
| 暑期安排10天集训 | 常规周课继续存在；日期相撞时提示，集训不自动替代常规课 |
| 两个同班学生 | 共同班级进度可继承；已有等级、掌握情况或营期选择不同，路线与建议可不同 |
| 仅推荐但未确定集训 | 能显示候选路线，不能把该营当作已经确认完成的条件 |
| 集训资料不足 | 不凭空生成缺失营的逐日课程与组合 |
| 考纲尚未录入 | 明确提示无法完成等级覆盖判断，不输出伪造匹配 |
| 老师调整时间 | 相关节点重新计算，已编辑文字不被无提示覆盖 |
| 资料库更新 | 历史定稿保持原内容，新版本可采用更新资料 |
| 多老师访问 | 只能编辑授权范围内学生；分配同班的老师可以协作 |
| PDF导出 | 内容与预览一致，页面和表格可读，包含版本信息 |
