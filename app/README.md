# 知程 · C++信奥学习规划工作台（本机 MVP）

## 打开网站

1. 双击本文件夹中的 `启动网站.cmd`，保持启动窗口打开。
2. 浏览器访问 <http://127.0.0.1:4317>。
3. 首次使用自行设置管理员账号和密码；以后用该账号登录。

网站只在当前电脑上提供服务。电脑重启或服务关闭后，需要再次运行启动文件。已保存的数据会保留。如果端口已经占用，先访问上述网址，避免重复启动。当前版本不提供密码找回，请保存好管理员账号。

## 使用顺序

1. 在“设置与 API”添加老师账号；在“我的班级”建立班级、分配老师、设置每周上课日和已完成课次。
2. 在“学生档案”添加年级、所属班级、已有等级和集训经历。默认继承班级进度，也能使用个人进度。
3. 在“课程与目标”维护课程知识点、目标大纲和资料核对状态。
4. 选择学生制定规划，填写完整周期、近期目标和寒暑假安排。近期目标期望月份可留空，系统会匹配整个周期内的后续GESP场次。可先生成规则排课草稿；配置 API 后可以生成 AI 路线。
5. 在“老师调整考级场次”选择指定月份并填写安排说明，点击“应用考级调整并重新匹配路线”；后续考级随之衔接，也可以恢复“按系统推荐”。期望月份不再阻止更早推荐，只有明确指定的场次才固定。
6. 查看“全周期考级匹配依据”，调整四列表格与学习建议，保存草稿、预览、保存定稿版本并导出 PDF。旧草稿可点击“重新匹配考级与路线”启用全周期匹配。老师改过的阶段会保留，前级考试推迟后，未锁定的后级随重新匹配顺延。
7. 在“课程与目标 → 认证日历”维护已公布的GESP日期和官网公告链接；未公布年份按3、6、9、12月候选场次计算。更新资料后需重新匹配当前草稿，历史定稿不变。

家长版预览和 PDF 使用橙色标题区、信息卡片及蓝色表格，分为“整体路线图”“本阶段学习建议”“阶段详解”三个部分。路线图第四列为“掌握重点与编程思维”，分“掌握”和“思维”两行，依据本阶段实际课次生成。学习建议仅一组，包含学习重点、ACGO课后任务、家长配合；阶段详解按路线逐项展示，常规课依据实际剩余课次生成模块，集训展示逐日大纲，考试阶段展示训练环节。右侧“训练与掌握要求”按课程内容区分训练任务、编程思维和掌握标准。老师可以在调整路线页修改建议、阶段目标、训练任务、编程思维、掌握标准与说明。

任务只展示单元主题、集训或考试名称；生成来源、模型及接口信息仅在老师工作台中显示。旧规划和历史定稿再次导出时也采用新样式，保存内容本身不被重写。教学资料缺口与时间待定等提示放入对应阶段的安排说明。

PDF 的阶段详解连续排版，剩余空间可容纳阶段目标和教学内容时直接接排；跨页会标记“（续）”并重复表头。常规课的左右表格可以分别延续，集训逐日表和考级训练表支持长行跨页。阶段标题与首段教学内容保持在一起，字号和课程内容不变。

旧规划若缺少冬令营逐日内容或 GESP 认证要求，在“调整学习路线 → 阶段详解”点击“更新课程资料”，会将当前资料库的大纲保存到草稿；历史定稿继续使用当时保存的资料。更新后请核对，再保存新的定稿版本。

## 绑定 API

管理员打开“设置与 API”，填写兼容 Chat Completions 的服务地址、模型名称和 API Key，保存后点击测试连接。服务地址填到 API 根路径，例如服务商提供的 `/v1`，不要附加 `/chat/completions`。具体模型名称以服务商文档为准；部分模型需要选择 `max_completion_tokens` 参数。

外部地址使用 HTTPS；本机模型允许 localhost HTTP。密钥只在后端使用，加密保存在本机，不回传到页面。更换服务地址时需要重新输入密钥。真实服务商和模型需用自己的 Key 测试；自动化检查使用本机模拟服务，不会产生外部模型费用。

AI 请求包含年级、学习进度、学习备注、已有等级、集训经历和课程资料，不包含学生姓名或班级名称。请勿在备注中填写不需要用于规划的个人信息。

接口格式参考：[Chat Completions 官方文档](https://developers.openai.com/api/reference/resources/chat)。

## 当前数据与边界

- U1 包含新增 8 次数理课，共 20 课；U2–U8 各 12 课，合计 104 课。课程库初始知识点以已收集的课名为基础，可继续补充详细教学内容。
- 每周一节推进一课，寒暑假照常；已有单元复习和测评不再额外增加周数。
- 寒假 D 系列按已收集的推荐条件匹配首营。班级课包映射需确认；20/30 天的后续衔接营仍待补齐规则，不自动拼接。
- 暑假已收集 XP01 与 XP03B 日程；冬季 D01–D05 已按用户截图补齐5个10天营的逐日主题与教学内容（2026-10-22）。各营先修条件、实际年份与营期仍需核对，详见 `docs/冬令营大纲资料汇总.md`。
- GESP 1–8、CSP-J 和 CSP-S 可选。GESP 已根据用户提供的31页认证标准导入 C++ 与共用要求，保留来源页码；文件正文未注明发布日期，标记为“用户提供版”，未核实是否为现行最新版。C++考纲已建立到具体课次及集训逐日主题的对应，未明确覆盖的范围保留待补项；课程主题只能支持教学时间推算，不能认定完整考纲覆盖。CSP 大纲仍待补齐。资料核对不代表学生掌握程度，当前不会将已学课次直接判定为具备晋级能力。详见 `docs/GESP-C++认证大纲资料汇总.md`。
- GESP匹配从已通过等级的下一级开始，每场最多建议一个等级，不自动跨级；近期目标后继续匹配到周期结束。核心课次未学到则顺延；补充知识、测评与报名资格是拟参加的前提。后续节点以此前等级按计划完成为前提，不写入学生已通过记录。
- 已公布日期按考试前一天的已排内容判断；未知日期保守计算到该月开始前。周期只覆盖考试月份的一部分且日期未知时，不强行安排。集训仅计入考试前的实际已排天数，拟参加集训形成条件说明。
- AI 在已计算的课次和时间范围内安排阶段任务、核心知识点、里程碑及建议。老师可以修改；手工调整阶段日期不会自动重排周课日历。
- 此版用于本机验证。多个教师账号具备班级访问限制，尚未开放其他电脑访问，也未部署公网。

## 数据与运行环境

数据位于 `app/.data/`。备份时先关闭网站服务，再完整复制该文件夹，包括 SQLite 数据库及 `master.key`。数据库和密钥文件须一起保留；能读取整个文件夹的人也可能解密 API Key。不要将该文件夹上传到公开仓库。

启动文件优先使用本机 Codex 自带 Node.js（24+）。PDF 导出使用本机 Codex 自带 Python、ReportLab 和微软雅黑字体。迁移电脑时需准备相同依赖，可通过 `PLANNER_PYTHON` 和 `PLANNER_FONT` 指定路径。

开发验证：在 `app` 目录执行 `node --test tests/*.test.mjs`。其中 PDF 分页检查使用合成资料验证续页表头、内容完整性和页面边界。隔离页面测试服务为 `node tests/preview.mjs`（4318 端口及 `.qa-data`），与正式本机数据分开。

考级安排修改后需先重新匹配，再预览、定稿和导出。尚未匹配的草稿会保留修改并提示处理；冲突场次会说明原因，不覆盖原有定稿。仅修改考级文字不固定时间；重新匹配会保留同一等级的阶段详解修改。
